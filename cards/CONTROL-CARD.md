# The Control card: design draft (before the netlist)
**Kehai Interim, 2026-11-18.** Worked out by reading the microsim's sequencer, decode and status code
(`microsim.js`: `cycle()`, `step()`, `decode()`, `sprRead/sprWrite`, `irqPending`). Every block below becomes chips in
`control-card.js`, tested the same way as the ALU card. Same rule: no processor, no programmable logic, no firmware.

## Blocks
| block | what it does | chips (first guess) |
| --- | --- | --- |
| **µPC** | 10-bit micro-address, counts for NEXT, loads otherwise | 3 × 74LVC161 (4-bit loadable counters) |
| **next-address select** | load source: CONST · dispatch · FETCH · TRAP_PROT · TRAP_BAD (fixed addresses are wired constants) | 5 × 74LVC153 + a few gates |
| **condition select** | one of 15 conditions → BR/BRN/WAIT | 2 × 74LVC151 (8:1) + local logic; card inputs SF±, QT±, BTOPNZ (from the ALU card, 2026-11-20), BADADDR, IORDY from other cards |
| **dispatch** | (mode, opcode) → routine address; unallocated opcodes are baked in as TRAP_ILL / T2_HALT | 2 × 10 ns SRAM (`dispatch.bin`) |
| **IR + decode** | 2 trytes from the bus; op = top 5 trits of IR0, rd/rs1 = diads, rs2 = low diad of IR1, imm9 = IR1 | 2 × 74ALVCH16823 |
| **register-slot select** | RF_SEL → 5-bit slot (rd/rs1/rs2 diad → 0..8 via a table; CONST; SP/T0/T1/FPC wired; SPR index) | 1 small table SRAM + 2 × 74LVC157 |
| **PC** | 27 trits, load from bus, +1 / −1, wraps at 9 trits in T2 | 2 × 16823 + **an incrementer**: 9 small slice tables, or 3 trytes of table |
| **micro-counter** | 0..63, load from the bus (needs a trits→binary table), inc, dec, =0 test | 2 × 74LVC161 + 1 table |
| **status latches** | MODE, PRIV, IE, IMASK, IPEND, PROT_EN, TRAP_DIV0 (the latch SPRs) | 74LVC574s + SPR-index decode |
| **interrupts** | IPEND set from the /IRQ lines; pending = IE ∧ mode ∧ (IPEND ∧ IMASK); priority encoder for IRQV and IRQ_ACK | 74LVC148-class encoder + gates |
| **bus sources** | PC, IMM (sign-extended imm9), CONST (14-bit binary → trits: a table), OPC, IRQV, SPR latch values | 245s / FET switches per source |
| **own control store** | this card's fields (SEQ, COND, CONST, RF_SEL, LD_PC, LD_IR, PC, RETIRE, UCNT, PSW, IRQ_ACK, BUS) | 5 chips + pipeline (BACKPLANE-PINOUT.md) |

## Things in the microsim the hardware has to reproduce exactly (found while reading)
1. **The step-boundary redirect.** At the start of every instruction step, `step()` ticks the step timer, then sends the
   sequencer to FETCH if an interrupt is pending and it isn't already there. The hardware equivalent is an
   end-of-step strobe (the next address is FETCH, or the word has RETIRE). That strobe ticks the timer and overrides the
   next address to FETCH when an interrupt is pending. The order (tick first, then test) matters: an IRQ raised by the
   tick must be seen at that same boundary.
2. **Aborted cycles jump to a trap.** When the Memory card's address check faults, the next address is TRAP_PROT or
   TRAP_BAD, so ABORT needs a second wire saying which. That's one more backplane pin (5 spare).
3. **The micro-counter loads from the bus** (`UCNT LOAD`, values 0..63). A ternary value has to become a 6-bit binary
   count: a small table on the bus's low trits.
4. **The PC counter is ternary** (+1, −1, load) and wraps at 9 trits in T2 mode. That needs its own incrementer, since
   the ALU is busy in those cycles.
5. **`ALIAS`** (rd = rs1 or rd = rs2 or rs1 = rs2) is a condition computed from IR fields: a few comparators, or a
   table.
6. **RETIRE also snapshots the flags.** The ALU card's control store now loads the shadow on the RETIRE words too
   (fixed today; the RETIRE words keep the flags, so it changes no result, and the rerun is still 0 mismatches).

## Test plan
- The card runs beside the microsim, like the ALU card. Inputs from the other cards come from the microsim: the status
  lines, ABORT plus fault kind, and the bus when Control isn't driving it.
- Compared every cycle:
  - the micro-address sequence;
  - everything Control drives onto the bus;
  - RSLOT and PORT;
  - PC, IR, the counter, every status latch, MODE/PRIV/IE.
- Mutants in the sequencer, dispatch, slot select, PC carry and interrupt priority.

# Stage 1 drawn (`control-card.js`, tested by `control-card-test.js`)
86 parts: 29 × 10 ns SRAM (control store ×6, tables), 8 × 74ALVCH16823 (pipeline ×3, IR ×2, PC ×3), 3 × 74LVC574
(micro-address ×2, micro-counter), 22 × 74LVC153, 10 × 74LVC157, 7 × 74LVC245, 1 × 74LVC32, 6 resistor packs.

**How it's built:** small lookup tables decide, and plain muxes and registers carry the decision out. There is no
program anywhere. The tables are generated by `control-tables.js` from the microsim's own rules, or repacked from
`roms/dispatch.bin`:
- **next address:** one table reads SEQ, the condition, ABORT plus fault kind, RETIRE, "jumps to FETCH", the
  step-boundary interrupt and IORDY. It picks increment / hold / CONST / dispatch / fixed address. A ±1 table does the
  micro-address increment;
- **conditions:** one table, holding the 11 conditions the microcode actually uses;
- **dispatch:** two tables addressed by the opcode's trits plus the mode bit;
- **decode:** a diad table gives the register slot and ALIAS; an SPR-index table and a port-number table read imm9;
- **PC:** 9 slice tables (hold / ±1 with carry ripple / load / T2 wrap / hold on ABORT);
- **micro-counter:** a next-state table plus a table that turns bus trits into a binary load value;
- **CONST onto the bus:** three binary-to-trits tables.

**Simulator change, found while drawing this card:** `netlist.js` now repeats passes until nothing changes, instead of
trusting placement order. That still fails on fights, on nets left undriven and on loops. The ALU card reruns
unchanged under it.

**Stage 2 (next):**
- the status latches;
- the interrupt logic (today's IRQP/IRQN inputs);
- the SPR port, where Control drives the latch SPRs onto the bus and tells the Registers card to stand aside. That's one
  more backplane line.

## Stage 1 results (`RESULTS-control-card.jsonl`)
The card runs one cycle behind the microsim. Compared every cycle: the micro-address, PC, IR, the micro-counter and its
zero flag, everything Control drives onto the bus, the register slot and the port number.

| workload | microcycles | Control drove the bus | mismatches |
| --- | ---: | ---: | ---: |
| 100 random programs (100 machine power-ups) | 300,000 | 62,029 | **0** |
| Desktop 1.1.2 boot | 400,000 | 79,749 | **0** |
| TritOS 2.1 | 400,000 | 87,261 | **0** |
| directed big-operand arithmetic | 37,543 | 5,483 | **0** |
| fetch-fault probe | 63 | 18 | **0** |

**Mutants: 5 of 5 caught.**
- condition ignored;
- trap address miswired;
- two dispatch bits swapped;
- PC carry skipping a slice;
- the step-boundary redirect missing.

The redirect mutant survived 300,000 random cycles. That's why `directed-irq-blockmove.js` exists, and it catches the
mutant within 345 cycles. The ALU card also passes that probe with 0 mismatches.

**A harness bug I caught on the way:** an aborted cycle still drives the bus in hardware; it's harmless, because
nothing loads. The first harness version flagged that as a mismatch. Now the bus isn't compared on aborted cycles.

# Stage 2 drawn: status latches, interrupts, SPR port (112 parts in all)
- **One 18-bit register** holds MODE, PRIV, IE, PROT_EN, TRAP_DIV0, IMASK (5) and IPEND (5). It's clocked every cycle;
  tables decide hold or change.
- **SPR writes need the bus value mod 32 and "is it nonzero?".** Three tryte tables give each tryte's value mod 32 and
  nonzero, and a combiner adds them (3^9 ≡ 3 and 3^18 ≡ 9, mod 32).
- **Next-state tables:**
  - one for the five single-bit latches (SPR write, then PSW ENTER/RESTORE, then hold on ABORT);
  - one each for IMASK and IPEND after a write;
  - one for IPEND after IRQ_ACK (clears the highest-priority pending and enabled line), then the device and timer
    sets.
- **Interrupt tables:**
  - pending now (for the IRQ condition), plus the IRQV vector number;
  - the same table on the next-state values: "pending at the coming boundary", which drives the redirect.

  Both were card inputs in stage 1; now they're computed on the card.
- **SPR reads:** a table puts any latch SPR onto the bus. A second SPR-index table raises **SPRNR**, the new backplane
  line that tells the Registers card to stand aside. FK (fault kind) got its backplane pin too: 109 signals, 3 spare.
- **Declared harness exception:** the test programs set SPRs directly in the microsim before running (`diff.js`, the
  boot scripts), so at each machine start the card's latch register is preset to those starting values. Nothing else
  is written from outside; device and timer interrupts arrive on the IRQSET input pins.

## Two simulator bugs found while drawing stage 2 (both fixed; every result on both cards rerun)
1. **A placement wiring miss in my own builder:** a text replacement meant to route the bus drivers' enable through
   the new SPR logic silently didn't apply. The new SPR probe caught it immediately.
2. **Stale nets in the fixpoint simulator.** In the version from earlier today, a driver that switched off in a later
   pass left its old value on the net, because the net was never cleared. Each pass now rebuilds every driven net from
   scratch. This could in principle have hidden mismatches, so **every Control and ALU workload and mutant has been
   rerun under the corrected simulator** (results below replace the earlier ones).

## Integration changes (2026-11-20)
- **UA is the next address.** The backplane UA0..9 now carries NA (through U105/U106 '244s, released in LOAD); U14/U15 hold
  the executing word's address (UPC) for the incrementer. This removes a one-word delay slot on every taken branch that
  only shows with all cards on one clock edge. The card test now clocks every register on one edge and runs in step
  with the microsim instead of one cycle behind. Mutant UA_IS_UPC.
- **The status latch resets to ISA-4's values** (MODE 1, PROTEN 1, the rest 0): U89's clears on RESET, MODE and PROTEN
  stored inverted through U104 ('04). Mutant LATCH_NO_RESET.
- **The clock/reset generator lives here** (clockgen.js, U200-U205, RN200): see INTEGRATION-PLAN.md.
